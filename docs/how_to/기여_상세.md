# GPT가 정리한 🧭 브랜치 생성부터 Pull Request(PR)까지의 안내서

안녕하세요! 이 프로젝트는 **안전한 협업**을 위해 다음과 같은 흐름으로 작업을 진행합니다.  
모든 변경 사항은 반드시 **Pull Request(PR)를** 통해 병합되며, `main` 브랜치에는 직접 작업하지 않아야 합니다.

---

## ✅ 전체 작업 흐름 요약

1. `main` 브랜치에서 작업 브랜치 생성  
2. 해당 브랜치에서 코드 작업  
3. 변경사항 커밋  
4. 작업 브랜치를 GitHub에 push  
5. GitHub에서 Pull Request(PR) 생성  
6. 리뷰 후 `main` 브랜치로 병합

---

## 🛠️ 1. 브랜치 생성

먼저 `main` 브랜치 기준으로 새로운 브랜치를 만들어주세요.

```bash
git checkout main            # main 브랜치로 이동
git pull                     # 최신 코드로 업데이트
git checkout -b feature/로그인페이지
```

브랜치 이름은 `feature/`, `bugfix/`, `docs/` 등으로 시작하는 게 좋아요.  
예시: `feature/login`, `bugfix/crash-on-start`, `docs/readme-update`

---

## ✍️ 2. 작업 및 커밋

원하는 작업을 하고, 변경사항을 커밋합니다.
본인이 원하는 기능이 완성될 때까지 이 단계를 계속 반복하세요.

```bash
git add .
git commit -F .gitmessage
```

> 커밋 메시지는 [.gitmessage](../../.gitmessage)를 참조하세요.

---

## 🚀 3. 브랜치 push

기능이 완성되었나요?
작업한 브랜치를 GitHub로 올립니다.

```bash
git push origin feature/로그인페이지
```

---

## 🔃 4. Pull Request 만들기

브랜치를 push하면, GitHub에서 **"Create pull request"** 버튼이 보입니다. 클릭하고 다음 내용을 입력해주세요:

- **Title (제목):** `Feat: 로그인 페이지 UI 구성`
- **Description (설명):** 변경한 이유, 핵심 내용 간단히 정리  
- **Base branch:** `main`  
- **Compare branch:** 내가 작업한 브랜치 (예: `feature/login`)

---

## 👀 5. 리뷰 받고 병합하기

- PR이 등록되면 팀원이 코드를 확인하고 댓글 또는 승인을 남깁니다.
- 리뷰가 완료되면, **Merge pull request** 버튼으로 `main` 브랜치에 병합합니다.
  - 병합 방식은 기본적으로 `Squash and merge`를 사용합니다.  
    → 여러 커밋을 하나로 정리해서 히스토리를 깔끔하게 유지합니다.

---

## 🧹 6. 브랜치 삭제 (선택)

병합이 끝나면 GitHub에서 작업 브랜치를 삭제하거나, 로컬에서도 삭제해도 좋습니다.

```bash
git branch -d feature/로그인페이지      # 로컬 브랜치 삭제
git push origin --delete feature/로그인페이지  # 원격 브랜치 삭제
```

---

## 💡 자주 묻는 질문 (FAQ)

**Q. 그냥 `main` 브랜치에서 작업하면 안 되나요?**  
A. 팀원들 코드와 충돌을 피하고, 리뷰 과정을 거치기 위해 **반드시 브랜치를 만들어서 작업해야 합니다.**

**Q. 커밋 메시지는 꼭 정해진 형식으로 써야 하나요?**  
A. **네**

**Q. PR이 뭐예요? 꼭 해야 하나요?**  
A. PR(Pull Request)은 내가 작업한 내용을 다른 사람에게 보여주고, 병합 전에 검토받는 절차입니다.  
팀 전체 코드의 품질을 지키는 핵심 과정이므로 반드시 필요합니다!

함께 만들어가는 협업 문화를 위해 꼭 위의 흐름을 지켜주세요! 🙌
